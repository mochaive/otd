# OTD: Orchestrating Things Done

**병렬 작업과 위임을 관리하기 위한 개인 태스크 관리 프레임워크.**

**전체 문서 → [otd.mochaive.com](https://otd.mochaive.com)**

---

## 문제

태스크 앱을 연다. 서른 개의 항목이 있다. 어떤 건 급하고 어떤 건 몇 주째 방치됐다. 어디서 시작할지 파악하는 데 10분을 쓴다. 결정할 때쯤이면 실제 작업에 써야 할 에너지를 이미 다 썼다.

또는: 지난주에 동료에게 뭔가를 넘겼다. 기억은 한다. 그런데 답장이 왔는지, 내가 답장해야 하는지, 그냥 흐지부지됐는지 모른다.

또는: 하루 끝에 도달한다. 하루 종일 바빴다. 그런데 실제로 무엇이 전진했는지 모르겠고, 목록 길이는 아침과 비슷해 보인다.

대부분의 시스템은 이걸 해결하지 않는다. 더 나은 목록을 준다. 목록은 여전히 자란다. 언제 끝났는지 알려주지 않는다.

---

## OTD가 다른 점

**작업 흐름마다 자기 레인이 있다.**
여러 프로젝트가 동시에 전진한다. 각 레인 안에서 단계들은 순서대로 진행된다. 다음에 뭘 할지 항상 안다. 서른 개 중에서 고르지 않는다. 다섯 여섯 개 중에서 고른다, 활성 흐름마다 하나씩.

**위임이 1급 개념이다.**
Do, Delegate, Await, Review: 동등한 가시성을 가진 네 가지 Mode. 사람이나 AI에게 넘기면 Await으로 이동한다. 결과가 돌아오면 Review로 올라온다. 루프가 닫힌다. 아무것도 사라지지 않는다.

**Today는 열린 목록이 아니라 닫힌 세트다.**
매일 아침 활성 Flow들이 올리는 것들로 Today를 만든다. Today의 모든 항목은 오늘 끝낼 수 있는 것이다. Today가 비면 끝이다. 시간이 다 됐기 때문이 아니라, 아침에 만든 세트가 완료됐기 때문이다. 절대 비지 않는 할 일 목록과 다르다.

## 프레임워크

| 개념 | 설명 |
|------|------|
| **Area** | 삶의 영역. 끝이 없다. |
| **Flow** | 구체적인 작업 흐름. 내부 순차, Flow 간 병렬. 관련 Flow는 `[[키워드]]` 접두사로 묶는다. |
| **Action** | 작업의 최소 단위. 하루 안에 완료 가능. |
| **Mode** | Do / Delegate / Await / Review: 누가 실행하고 어떤 상태인가. |
| **Today** | 오늘 건드릴 Action들의 모음. 비면 오늘 할 일이 끝난 것. |
| **Stuck Signals** | 임계치 기반 정체 진단. 결정을 피할 수 없게 만든다. |

모든 것의 기반이 되는 두 원칙: *머리를 비워라.* 그리고 *오늘을 직접 설계하라.*

## OTD로 보내는 하루

```
Area: 사이드 프로젝트
  ├─ Flow: [[앱 런칭]] MVP 개발       →  [Do]       기술 스펙 작성
  └─ Flow: [[앱 런칭]] 런칭 마케팅    →  [Delegate] AI에게 랜딩 페이지 카피 요청

Area: 커리어
  └─ Flow: 이직 준비                 →  [Review]   어제 위임한 연봉 리서치 결과 검토

Area: 건강
  └─ Action                         →  [Do]       건강검진 예약
```

```
07:00  Daily Review: Today 설정
08:00  Review  → 연봉 리서치 승인. Flow의 다음 Action 열림.
09:00  Delegate → 랜딩 페이지 요청 발송. Await으로 전환.
10:00  Do      → 기술 스펙 완료. 건강검진 예약 완료.
12:00  Today 비어있음. 끝.
```
