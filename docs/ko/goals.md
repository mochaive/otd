# Goals

Goal은 1~2년 안에 향하고 싶은 방향이다. 독립적으로 존재한다 — Area 안에도, Flow 안에도 속하지 않는다.

---

## Goal이란 무엇인가

Goal은 이 질문에 답한다: **앞으로 1~2년 안에 무엇을 이루고 싶은가?**

Goal은 태스크가 아니다. Today에 Action을 올리지 않는다. Flow를 포함하지 않는다. 독립적으로 존재하고, 분기별로 검토되며, 어떤 Flow를 활성화할지를 결정하는 데 쓰인다.

Goal 예시:
- "2026년 말까지 시니어 엔지니어로 전환"
- "재정적으로 지속 가능한 사이드 수익 구축"
- "하프마라톤 완주"
- "앱 첫 번째 공개 버전 출시"

---

## Goal이 Flow와 다른 점

OTD에서 가장 중요한 구분이다.

| | Goal | Flow |
|--|------|------|
| 기간 | 1~2년 | 수일~수개월 |
| 성격 | 방향 | 활성 작업 |
| 포함하는 것 | 없음 (구조적으로) | 순차 Action들 |
| 검토 주기 | 분기 | 매주 |
| Action 생성 | 아니오 | 예 |

"시니어 엔지니어로 전환"이라는 Goal은 직접 Action을 만들지 않는다. 하지만 어떤 Flow를 활성화할지를 알려준다: "포트폴리오 준비", "AWS 자격증 취득", "사내 주요 이니셔티브 리드". 그 Flow들이 실제 작업을 하는 Action을 포함한다.

Goal은 Flow의 이유다. Flow는 Goal의 방법이다.

---

## Goal은 독립적이다

Goal은 특정 Area에 속하지 않는다. 하나의 Goal이 여러 Area에 걸칠 수 있다.

"재정적으로 지속 가능한 사이드 수익 구축"은:
- Area: 사이드 프로젝트 (제품 개발)
- Area: 재정 (수치 파악)
- Area: 커리어 (포지셔닝과 네트워킹)

이것이 Goal을 Area에 붙이지 않는 이유다. Goal은 구조를 가로지르는 별도 레이어다.

대부분의 Goal이 주요 Area 하나와 연관되는 건 사실이다. 그렇게 생각하는 건 괜찮다 — 단, 여러 Area에 걸친 Goal을 억지로 하나에 붙이지는 마라.

---

## Goal 개수

활성 Goal을 3~7개로 유지한다. 그 이상이면 현실적으로 전진시킬 수 있는 것보다 많은 Flow를 가지게 된다. 그 이하면 충분히 앞을 내다보지 못하는 것이다.

Goal이 더 이상 관련이 없다면 — 상황이 바뀌었거나, 우선순위가 달라졌거나 — Someday로 옮기거나 삭제한다. Goal은 낡는다. 검토하라.

---

## 좋은 Goal 작성하기

좋은 Goal은:
- **판단할 수 있을 만큼 구체적이다** — "건강해지기"는 Goal이 아니다. "5월까지 하프마라톤 완주"는 Goal이다.
- **1~2년 안에 달성 가능하다** — 10년이 걸린다면 Vision이다. 한 달이면 그냥 Flow다.
- **활동이 아닌 결과다** — "앱 작업하기"는 활동이다. "첫 번째 공개 버전 출시"는 결과다.

SMART 형식 같은 정교한 포맷은 필요 없다. 명확한 문장 하나면 충분하다.

## Review에서의 Goal

Goal은 두 가지 주기로 검토된다.

**Weekly Review — 짧은 확인:**
활성 Goal을 훑는다. 각 Goal에 대해: 현재 이 방향으로 전진 중인 Flow가 있는가? 막히거나 빠진 것이 있는가?

깊이 파고들 필요는 없다. 2분간 목록 스캔: "Goal 1 — 포트폴리오 Flow 진행 중, 맞음. Goal 2 — 활성 Flow 없음, 뭔가 시작해야 하나?"

**분기 Review — 본격적인 점검:**
1. 각 Goal 검토: 여전히 관련 있는가? 필요하면 업데이트하거나 은퇴시킨다.
2. 각 Goal에 현재 기여 중인 Flow를 매핑한다.
3. 활성 Flow가 없는 Goal이 있는가? 하나를 활성화한다.
4. 어떤 Goal에도 기여하지 않는 Flow가 있는가? Someday 이동을 고려한다.
5. 새로 생긴 Goal을 추가한다.

Goal ↔ Flow 매핑은 항상 Review에서 이루어진다 — 고정된 구조적 연결이 아니다. Flow는 왔다 갔다 하지만 Goal은 더 안정적이다. 연결을 구조가 아닌 동적으로 유지하면 시스템 관리가 더 쉽다.

## Goal vs. Vision, Purpose

| | Goal | Vision | Purpose |
|--|------|--------|---------|
| 기간 | 1~2년 | 3~5년 | 무기한 |
| 검토 | 분기 | 연간 | 연간 이하 |
| 연결 대상 | Flow | Goal | Goal / Area |

Vision과 Purpose는 Goal이 아니다. Goal이 올바른 방향을 향하고 있는지를 알려주는 더 긴 범위의 배경이다. [Reference](/ko/reference)에 보관하고 연간으로 검토한다.

흐름: Purpose가 Vision을 만들고, Vision이 Goal을 만들고, Goal이 Flow를 활성화하고, Flow가 Today에 Action을 올린다.
